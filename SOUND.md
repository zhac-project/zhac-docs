# Hub sounds

The wired hub (`zhac-wired-core`, ESP32-S31 and ESP32-P4 boards) can play sounds through the speaker on
its board: a doorbell chime, an exit beep while the alarm arms, a siren. Every sound is generated by the
hub. There are no sound files to upload, and the microphone is not used.

You can play a sound from a rule, from a Lua script, from the hub page (**Settings › Sound**), from the
REST API, and as the siren of a **Safety** profile (the **Hub Sound** device).

A board without the speaker parts boots and runs as before; see [No speaker found](#no-speaker-found).

## Boards and pins

Both supported boards carry the same parts: an ES8311 audio codec, an NS4150B amplifier and a speaker
header. The hub plays 16 kHz mono sound.

| | ESP32-P4-NANO / Guition JC-ESP32P4-M3-DEV | ESP32-S31 Function-CoreBoard-1 |
|---|---|---|
| Speaker | the P4-NANO kit's 8 Ω, 2 W speaker | a speaker header for 4 Ω, 3 W |
| Codec I2C SDA / SCL | GPIO 7 / 8 | GPIO 51 / 50 |
| I2S MCLK / BCLK / LRCK / DOUT | GPIO 13 / 12 / 10 / 9 | GPIO 52 / 53 / 55 / 56 |
| Codec ASDOUT to the chip (reserved, never driven) | GPIO 11 | GPIO 54 |
| Amplifier enable (high = on) | GPIO 53 | GPIO 57 |

The pins are set in the firmware build (`CONFIG_ZHAC_AUDIO_*`) and are the same on every unit of a board.
Audio is on in the release images of both boards. The hub switches the amplifier on only while a sound
plays, and off again about a second after it ends. The amplifier stays silent for a moment after it
switches on, so a sound that starts while it is off begins about 0.15 s late
(`CONFIG_ZHAC_AUDIO_PA_LEAD_MS`). A sound within about a second of the last one starts at once.

### GPIO53 on the P4

On the P4, GPIO53 is the amplifier pin. It is no longer one of the pins you can set up in
**Settings › I/O** (see [GPIO.md](GPIO.md#which-pins)). A hub that already has a user pin on GPIO53 drops
that row at boot (the boot log says why), and **Settings › I/O** no longer lists it. Add the pin again on
another GPIO in **Settings › I/O**. The S31's pin lists contain none of the audio pins.

When the codec answers at boot, all eight audio pins belong to the firmware and **Settings › I/O** never
offers them.

## Volume and mute

- **Volume runs 0 to 100** in rules, Lua and the REST API, but the hub never plays louder than **70**,
  whatever asks (`CONFIG_ZHAC_AUDIO_MAX_VOLUME`, a build setting). A louder value is played at 70, not
  refused. The slider on the hub page ends at 70.
- 70 was set by ear on the P4-NANO kit's 8 Ω, 2 W speaker. Another speaker can sound louder or quieter at
  the same number, so start low.
- **The default volume is 40.** A sound without a volume of its own plays at the default. A volume given
  with a sound (`sound.play beep 60`) applies to that sound only.
- The default volume and the mute switch are kept across restarts.

### Mute and urgent sounds

Four sounds are **urgent**: `alarm`, `siren`, `fire` and `co`. Only one sound plays at a time, and a
new one replaces the one playing, with one exception: a normal sound never replaces an urgent one.

| | Normal sounds (the other 12, and tones and melodies) | Urgent sounds |
|---|---|---|
| Muted | not played; one that is playing stops | still played, so a muted hub still sounds the alarm |
| An urgent sound is playing | refused (`an urgent sound is playing`) | replaces it |

A doorbell chime therefore cannot cut off a siren. A rule whose `sound.play` is refused for that reason
shows `action_error:sound.play` as its last skip (see [RULES_DSL.md](RULES_DSL.md#rule-status-and-run-now)).
A rule that plays a sound while the hub is muted does nothing and is not an error.

To keep the speaker out of the alarm altogether, do not list **Hub Sound** among a profile's outputs and
write no rules or scripts that play urgent sounds.

### Loops

A looping sound repeats, with a pause that belongs to the sound, until one of three things happens: a
`sound.stop`, another sound replaces it, or 10 minutes have passed. Only some sounds can loop (the table
below).

## Built-in sounds

Sixteen sounds, all generated. `Length` is one pass in milliseconds, without the pause a loop adds;
`GET /api/sound` lists the same figures.

| Name | Sounds like | Length | Loops | Urgent |
|---|---|---|---|---|
| `beep` | one short beep | 120 | yes | |
| `double_beep` | two short beeps | 300 | yes | |
| `triple_beep` | three short beeps | 400 | yes | |
| `chime` | a soft two-note ding | 1000 | | |
| `doorbell` | the classic two-note ding-dong, decaying | 1500 | | |
| `westminster` | the Westminster quarters, two four-note phrases, as a doorbell | 4250 | | |
| `notify` | a gentle rising two-tone | 280 | | |
| `success` | a rising three-note arpeggio | 400 | | |
| `error` | a falling low two-tone | 500 | | |
| `warning` | four medium pulses | 1050 | yes | |
| `armed` | two rising chirps | 280 | | |
| `disarmed` | one falling chirp | 200 | | |
| `alarm` | fast high/low alternation | 500 | yes | yes |
| `siren` | a rising and falling wail | 3000 | yes | yes |
| `fire` | three beeps, a pause: the pattern smoke alarms use | 2500 | yes | yes |
| `co` | four short beeps, a pause: the pattern CO alarms use | 700 | yes | yes |

Besides these, Lua can play a free **tone** (one pitch) and a **melody** of up to 32 notes. Both are
normal sounds and do not loop.

## Rules

Two actions, see [RULES_DSL.md](RULES_DSL.md#actions):

```
sound.play <name> [<volume>] [loop]
sound.stop [<name>]
```

`sound.stop` without a name stops whatever plays. With a name it stops only if that sound is playing, so
the end of one alarm profile cannot silence another profile's sound.

A rule that names a sound that does not exist, or asks `loop` of one that cannot loop, is refused when it
is saved, and the answer lists the valid names.

```
ON Mqtt#zhac/home/doorbell DO sound.play westminster ENDON
ON hall_button#action="single" DO sound.play chime ENDON
```

### Exit and entry beeps for an alarm profile

[ALARM.md](ALARM.md#your-own-reactions) explains the named events `Event#alarm_<state>_<id>`. These
rules use the intrusion profile `away`; put another profile's id in place of `away`.

```
# Exit beep while the arm delay runs, a chirp once armed
ON Event#alarm_arming_away DO sound.play beep 50 loop ENDON
ON Event#alarm_armed_away DO sound.play armed ENDON

# Entry beep while the entry delay runs
ON Event#alarm_pending_away DO sound.play double_beep 60 loop ENDON
ON Event#alarm_triggered_away DO sound.stop double_beep ENDON

# A disarm ends either beep and chirps
ON Event#alarm_disarmed_away DO sound.stop beep; sound.stop double_beep; sound.play disarmed ENDON
```

- With an arm delay of 0 the profile skips `arming`, so no exit beep starts and `armed` chirps at once.
- If the profile lists the **Hub Sound** device as an output, its urgent siren sound takes over from the
  entry beep when the alarm goes off, so the `triggered` rule only matters without it.
- If a siren still plays when the profile is disarmed, `sound.play disarmed` is refused (an urgent sound
  is playing) and the chirp is skipped.

Rules can also drive WS281x strips (`strip.set`, `strip.off`), see [RULES_DSL.md](RULES_DSL.md#actions).

## Lua

Six functions on `zhac`, none of them blocks. Full entries in [LUA_API.md](LUA_API.md#5-zhac-module-reference), 5.22 to 5.27:

| Call | Returns |
|---|---|
| `zhac.sound_play(name [, volume [, loop]])` | `true`, or `nil, err` |
| `zhac.sound_tone(hz, ms [, volume])` | `true`, or `nil, err` |
| `zhac.sound_melody({ {hz, ms}, ... } [, volume])` | `true`, or `nil, err` |
| `zhac.sound_stop([name])` | `true` |
| `zhac.sound_volume([v])` | the default volume in force |
| `zhac.sound_playing()` | the name playing (`"tone"` and `"melody"` for those), or `nil` |

```lua
zhac.sound_play("doorbell")
zhac.sound_play("beep", 60, true)         -- looping, volume 60
zhac.sound_tone(880, 300)
zhac.sound_melody({ {523, 150}, {659, 150}, {784, 300}, {0, 100}, {1047, 400} })   -- hz 0 is a rest
if zhac.sound_playing() == "beep" then zhac.sound_stop("beep") end
```

A refusal comes back as `nil` and the reason: `muted`, `an urgent sound is playing`, `unknown sound`,
`this sound cannot loop`, `bad value (volume 0-100, hz 100-7900, ms 1-10000, 1-32 notes)`,
`no speaker on this hub`, or `speaker off: <why>` when the speaker is there but did not start (see
[No speaker found](#no-speaker-found)). A volume, pitch or length that is not a whole number (`40.5`,
`"loud"`) is a bad value too: the script gets `nil, err` and goes on.

Pitches run from 100 to 7900 Hz. The sample rate is 16 kHz, so the highest pitches come out weak.

## REST

Local only. **Auth required**, as for `/api/io`. See [REST_API.md](REST_API.md#hub-sound) and
[openapi.yaml](openapi.yaml).

| Request | Body | Reply |
|---|---|---|
| `GET /api/sound` | | `{"present", "volume", "max_volume", "muted", "playing", "sounds": [{"name", "ms", "loop", "urgent"}]}` |
| `PUT /api/sound` | `{"volume"?: 0-100, "muted"?: true/false}` | the same state (`volume` as held to the maximum) |
| `POST /api/sound/play` | `{"name": "<sound>", "volume"?: 0-100}` | `{"ok": true}` |
| `POST /api/sound/stop` | | `{"ok": true}` |

A refusal is `400 {"error": "<why>"}` with the same texts as in [Lua](#lua). `POST /api/sound/play`
does not loop. If the codec was found but did not start, `GET /api/sound` adds an `error` text.

## The Hub Sound device

While the speaker is there, the device list shows **Hub Sound** (model `ZHAC-SOUND`), like Hub I/O and
Alarm. Its IEEE address is `0x025A484143534E00`. It has one writable value, `warning`, in the shape of a
Zigbee siren's, so the **Safety** page lists it among the devices a profile's outputs can use. Pick it as
an output of kind `warning` and the profile's alarm sounds through the hub's own speaker, with no rule.

The alarm sends `warning` as `mode,level,strobe,seconds` to start and `false` to stop. The device plays
this through the same player as rules and Lua:

| In `warning` | Hub Sound does |
|---|---|
| mode `burglar` | plays `alarm`, looped |
| mode `fire` or `fire_panic` | plays `fire`, looped |
| mode `emergency`, `alarm`, `ON`, `police_panic` or `emergency_panic` | plays `siren`, looped |
| mode `stop` or `OFF`, or the value `false` | stops the sound the device started, if it still plays |
| level `low`, `medium`, `high`, `very_high` | volume 25, 40, 55, 70 (then held to the maximum); no level means `medium` |
| strobe `1`, `true`, `0`, `false` | accepted and ignored |
| seconds | stops after that many seconds, 600 at most; no seconds means 10; `0` stops |

- Write a text like `burglar,high,1,60`: the words exactly as above, no spaces, one to four fields,
  none empty. Anything else is refused.
- A plain `true` is a siren for 10 seconds, and a whole number *n* is a siren for *n* seconds
  (`0` stops, 600 at most).
- A rule or a script can drive the device like any siren, by its IEEE address:
  `zigbee.set 0x025A484143534E00 warning burglar,high,1,60`, or in Lua
  `zhac.set_attr("0x025A484143534E00", "warning", "emergency,high,1,30")`. For an everyday chime,
  `sound.play` is simpler.
- Its sounds are urgent, so mute does not silence it and a normal sound cannot cut it off.
- Stopping ends only a sound the device started. A `siren` you played from a rule or script is yours to
  stop with `sound.stop`.
- However long a profile's alarm time is, the sound ends after 10 minutes at the most.
- When two profiles list the device, it behaves like a shared Zigbee siren: see
  [Outputs](ALARM.md#outputs).
- In Home Assistant (MQTT discovery) the device is a switch whose state stays unknown, as `warning`
  takes writes only. On sends `1`, a siren for one second; off sends `0` and stops it.

The device exists only while the codec is there. On a board without it the entry is removed at boot.

## No speaker found

At boot the hub reads the ES8311's chip ID over I2C. If the chip answers with the right ID, the hub starts
audio. If not, the hub:

- claims none of the audio pins, so a board without the codec keeps every pin it had;
- shows **No speaker found on this board** in **Settings › Sound**, and `GET /api/sound` answers
  `"present": false`;
- answers every play with `no speaker on this hub`, and refuses a rule with a `sound.play` or
  `sound.stop` when it is saved (`no speaker on this hub`);
- has no Hub Sound device.

A codec that answers but fails to start (for example an I2S error) also leaves audio off for that boot:
a sound asked for while the hub was starting never plays, and from then on:

- every play is answered with `speaker off: <why>`, for example
  `speaker off: I2S setup failed: ESP_ERR_INVALID_STATE`, and a rule that tries to play logs that text;
- a rule with a `sound.play` or `sound.stop` is refused with that text when it is saved; rules saved
  before still load;
- the Hub Sound device stays in the device list, but its periodic last-seen updates stop, and it
  refuses a new `warning`.

The reason is also in `GET /api/sound` (`error`) and in the boot log.
