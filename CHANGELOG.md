# Changelog

All notable changes to **zhac-docs** are documented in this file.

## [Unreleased]

### Added

- **`ALARM.md` is Safety: alarm profiles** for intrusion, water, fire and gas: the Alarm device with one attribute per profile, how it works (every profile, the six steps of each change), profiles and classes, states, arming, disarming and silencing with who can do what, what sets it off (also water leak, smoke, gas and CO sensors), outputs (a switch set to a value and left so, one device in several profiles), keypads, notifications, rules and Lua on a profile's attribute and on `Event#alarm_<state>_<id>`, arming from outside, updating from v2026112401 and going back, limits. `WS_API.md` names the section Safety and has `alarm.get`, `alarm.arm {id}`, `alarm.disarm {id?}`, `alarm.silence`, `alarm.config.set`, the `alarm.changed` push and the profile config; the hub's own socket takes frames up to 32 KB (the cloud relay keeps 8 KB). `FEATURES.md` (WC12) and `README.md` name Safety. The zhac.org card and footer keep their wording until the release that carries Safety. From the final review of the firmware: `alarm.config.set` needs `profiles` as a list (the v2026112401 form is converted only from the hub's stored record); only a missing `id` names no profile, and `null`, `""` or a non-text `id` is "no such profile"; `alarm.get` answers `oom` rather than part of the config; melody and volume are up to 23 bytes of UTF-8 (not "characters"); a config edited on v2026112401 during a fall back is carried while the Safety page has not saved yet, and a mode armed there comes back by id, else by keypad button (a renamed profile keeps it); at the boot stop after a restart during an alarm, outputs left so get their value again. `SECURITY.md` gives the WebSocket frame cap as 32 KB (32,768 bytes).
- **`ALARM.md`: security mode**, the hub's built-in alarm panel (stage 1): states, what sets it off, sirens, keypads, notifications, rules and Lua that react to it, who can disarm, limits. `WS_API.md` gets the `alarm.*` commands and the `alarm.changed` push, `RULES_DSL.md` the text values of `zigbee.set` (`effect blink`, a siren's `warning burglar,high,1,180`, `alarm_state armed_away`), `FEATURES.md` row WC12. Covers `Event#alarm_arm_failed` (an arm refused for open doors or windows, not from the hub page), the siren check on save, notifications held back while the network is down, the 19-character rule value, and `on` / `off` / `true` / `false` as 1 / 0 in `zigbee.set`.
- **`ALARM.md` explains how security mode works**: what goes in, the state machine, the clock, what each change does and in which order, a restart, and where it lives in the firmware. `README.md` now lists `ALARM.md` and `GPIO.md`, and `FEATURES.md` marks WC12 as run on hardware.
- **zhac.org: a security mode card** among the features ("An alarm panel built in", linking `ALARM.md`) and a "Security mode" link under Docs in the footer.
- **`SOUND.md`: hub sounds and strip rule verbs.** The hub's speaker: the boards and their pins (the P4-NANO kit's 8 Ω, 2 W speaker and the S31's 4 Ω, 3 W header), the volume (0–100, never above 70, default 40), mute against the urgent sounds (`alarm`, `siren`, `fire`, `co`), the 16 generated sounds, ready exit and entry beep rules for a Safety profile, the Hub Sound device that sounds a profile's alarm and the `warning` values it takes, and what a board without the codec does ("No speaker found"). `RULES_DSL.md` has `sound.play`, `sound.stop`, `strip.set` and `strip.off`; `LUA_API.md` §5.22–5.27 `zhac.sound_play`, `sound_tone`, `sound_melody`, `sound_stop`, `sound_volume` and `sound_playing`; `REST_API.md` and `openapi.yaml` `/api/sound`; `ALARM.md` the Hub Sound output; `GPIO.md` the strip verbs and no GPIO53 in the P4 pin lists (it is the amplifier pin now: a hub with a user pin there shows that row's error after the update, so move the pin in Settings › I/O). `FEATURES.md` row WC13, `README.md` lists `SOUND.md`.

### Changed

- **`ALARM.md` and `WS_API.md` follow the Safety fixes**: three more reserved profile ids (`pin_code`, `action_code`, `color_hex`); a sensor error names the row as sent, and a 49th sensor and a sensor listed twice have their own messages; a keypad panic during an arm delay still runs the hazard check when it ends in `armed`; after a restart during an alarm the hub switches off the outputs of the config in force at the restart, at once on any disarm, and again after a second restart in that minute (record `bt`), but never sends a switch the opposite of the value the config in force then leaves it at; a save writes the states with the config; kept outputs follow the config the alarm went off under; the rule and device names the Safety page builds (the hub's rules skip removed devices when they look a name up), and the names of template copies.
- **`SECURITY.md` describes the hub firmware, zhac-wired-core**: the threat model (the P4 ↔ C6 radio UART instead of the two-chip SPI bus), sign-in (lockout, the cross-site check, the WebSocket sign-in deadline), the attack surface (the web UI packed in the firmware, the cloud link), the hardening settings, and OTA: `https://` only, this firmware's own images, no older release unless asked, the trial with rollback, and no signature check. The S3 / P4 OTA routes and `/metrics` are gone.
- **`FEATURES.md` §5 describes the hub's REST and WebSocket APIs**: §5a HAP is marked archived; §5b lists the routes the firmware has (sign-in lockout and the cross-site check instead of rate limits and CORS, `device.get`, `ota.update`); §5c no longer names the dual-chip builds; L19 points at the Bind tab and `POST /api/group/cmd`; S20 Improv is not on the hub.
- **The flasher no longer calls the Waveshare ESP32-P4-NANO untested** (`flash/index.html`): the maintainers' hub has run on one since 2026-10-13. The Module-DEV-KIT stays untested.
- **The API references describe the hub firmware, zhac-wired-core** (`REST_API.md`, `WS_API.md`,
  `LUA_API.md`, `openapi.yaml` 0.4.0): they described the archived S3 net core. Each route,
  WebSocket command and push event is now one the firmware has: the 19 documented routes it never
  had are gone, the 31 it had undocumented are in, and every implementation pointer names a file
  in zhac-wired-core or zhac-components. `HAP_PROTOCOL.md` and `ZNP_API_CONTRACT.md` are marked
  archived; `RULES_DSL.md`'s link to the Lua triggers works again.
- **`FIRST_20_MINUTES.md` follows today's flasher, for both boards**: the ESP32-S31 path next to the P4 + C6 one; on the P4, the one-time radio installer replaces the USB-serial wiring (by wire stays as the flasher's Advanced section), and the flasher picks the silicon family, so the manual revision check and the "v3.x will not boot" step are gone (v3.0 stays unsupported). The status note says what runs on hardware; Backups names the full backup.
- **Issues and Discussions move here from zhac-platform** (archived): `.github/ISSUE_TEMPLATE/` (bug, device request, board report; the dual-chip and single-chip choices dropped, the label commands now name this repo). Every "report a bug", "request a device" and Discussions link — zhac.org, the flasher, supported devices, `FIRST_20_MINUTES.md`, `TROUBLESHOOTING.md`, `HOME_ASSISTANT.md` — points here. Before the forms work: enable Discussions on this repo and create the labels (commands in `config.yml`).
- **The browser flasher no longer offers the dual-chip images** (`flash/index.html`, `flash/build-site.sh`): that build never shipped and is archived; its releases stay on GitHub.
- **README describes the one-board hub** (zhac-wired-core on the ESP32-S31 or the Guition P4 + C6): new architecture and repository sections, the archived repos listed as such, and the dual-chip wiring and build guide replaced by a pointer to zhac-wired-core's build guide. `FEATURES.md` lists the dual-chip and single-chip builds as archived; `CONTRIBUTING.md` and `SECURITY.md` point at the live repos.

### Added

- **Zigbee device firmware update** (`REST_API.md`, `openapi.yaml`, `FEATURES.md` WC11): `POST /api/device/ota`, `GET /api/device/ota` and `POST /api/device/ota/cancel` on the wired builds: the file check, one update at a time, no older versions, the states and reason codes, and that the hub now answers devices' OTA queries ("no image" while none is loaded).
- **Full backup and restore** (`REST_API.md`, `openapi.yaml`, `FEATURES.md` WC10): `POST /api/backup/full` and `POST /api/backup/restore` on the wired builds, the file's encryption, the restore's checks and error codes, and `tools/zhac_backup.py` for a computer or a USB restore.
- **Hub GPIO control** (`RULES_DSL.md`, `LUA_API.md`): the rule actions `gpio.set`, `gpio.toggle` and `pwm.set` (with an inputs-as-trigger example), and the Lua functions `zhac.gpio_write`, `zhac.gpio_toggle`, `zhac.gpio_read`, `zhac.pwm_write`, `zhac.adc_read` and `zhac.ws_write`. Only pins configured in Settings › I/O can be used.
- **`GPIO.md`**: configuring hub pins, the pins each board offers, the Hub I/O device, and wiring notes (3.3 V logic, current, relays, buttons, ADC range, WS2812 power and data level).
